# LUMEN – a Computer Graphics game (Unity 6 / URP)

A neon synthwave arcade game in which every system is also a live Computer Graphics demonstration.
You are a glowing **light orb** on a procedurally generated terrain. Collect **12 Light Shards** in **180 s**, avoid the
**Sentinels** (they patrol Bézier loops and chase you when they see you), stun them with a **light pulse** (ray cast), then enter the **Portal**.

Score = `time left × 10 + shards × 100`. You have 3 health points.

## Controls
| Key | Action |
|---|---|
| WASD | Move (camera-relative) |
| Space | Jump (press again in the air to boost) |
| Left mouse | Fire light pulse (ray cast) |
| Mouse | Orbit camera |
| Tab | CG Lab Panel (time ×0.25 while open) |
| 1 – 5 | Shading: Flat / Gouraud / Phong / Blinn-Phong / Toon |
| P | Perspective ↔ Orthographic (animated matrix morph) |
| F | Wireframe overlay |
| N | Vertex normals |
| Z | Z-buffer (depth) view |
| B | Bézier / Catmull-Rom curves |
| H | RGB→HSV hue shift (also triggers when you are hit) |
| R | (Lab Panel open) regenerate the world with a new seed |
| Esc | Pause menu (closes the Lab Panel first if open) |

## How to run
1. Open the project (`E:\PROJECTS\cggame\My project`) in **Unity 6** (6000.6.x, URP 17, Input System package).
2. Open `Assets/_Lumen/Scenes/MainMenu.unity` and press **Play**.
3. If the scenes/materials ever need regenerating: menu **Lumen → Build Materials and Scenes** (also sets Build Settings: MainMenu, Game).
4. Sanity tests for the hand-written algorithms: menu **Lumen → Run Algorithm Tests** (results in the Console).

No external assets are used – meshes, textures, particles and shaders are all generated by code.

## How to build an .exe
`File → Build Profiles / Build Settings` → platform **Windows, Mac, Linux** → target **Windows** → scenes should list `MainMenu` and `Game`
(already set) → **Build** and choose a folder. Run the generated `.exe`.

## 2-minute demo script for the examiner
1. **0:00 – Menu.** "LUMEN: every system is a CG algorithm." Show the *CG Concepts* page. Press **Play**.
2. **0:15 – Intro.** The camera flies along a **Catmull-Rom spline** (concept 5). Press **B** to show the spline and the Sentinels' **cubic Bézier** loops with control polygons (de Casteljau).
3. **0:35 – Terrain & shading.** "200×200 mesh from hand-written fractal Perlin noise, normals by cross products." Press **1 → 5**: Flat, Gouraud, Phong, Blinn-Phong, Toon (outline pass). Point out the orb as a moving **point light with 1/(a+bd+cd²) attenuation**.
4. **0:55 – Views.** **F** wireframe (barycentric geometry shader), **N** normals, **Z** Z-buffer (linearised depth), **P** perspective→orthographic matrix morph.
5. **1:15 – Lab Panel (Tab).** Show ka/kd/ks/shininess sliders, FOV, and the **live 4×4 matrix** of the nearest shard (T·Ry·Rx·S). Open *Radar*: toggle **DDA vs Bresenham** (pixel counts + timings) and **Show unclipped geometry** (Cohen-Sutherland / Sutherland-Hodgman).
6. **1:35 – Gameplay.** Fire the **light pulse** (ray–AABB + ray–sphere) at a Sentinel; it stops spinning/stunned (quaternion slerp turning). Jump → squash & stretch. Get hit → **HSV hue-shift** effect. Collect shards → particle bursts.
7. **1:55 – Finish.** With 12 shards the portal opens (**keyframe animation**, wave shader). Enter it → win screen with score. Mention the algorithm tests (`Lumen → Run Algorithm Tests`).

## Known limitations
* Z-buffer view is produced by the lit shader from the fragment's hardware depth (not a full-screen pass sampling `_CameraDepthTexture`) – see `CG_CONCEPTS.md`, concept 8.
* Wireframe uses a geometry shader (DX11/Metal-with-geometry-fallback; not on GLES/WebGL).
* The hue-shift effect samples the opaque colour texture, so additive particles are not hue-shifted.
* UI is immediate-mode (IMGUI) so it works with the Input System package alone and needs no assets.
* The `godMode` field on `GameManager` is a debug switch used for automated verification; it is off by default.
